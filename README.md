# Консольные приложения Client и Server

Client позволяет управлять параметрами подключения и передачи данных. Server позволяет вычислять расстояние до заданной позиции.

## Краткое описание

Оба приложения предоставляют консольный интерфейс с интерактивным текстовым меню. Конфигурация приложений может быть загружена из JSON-файла, либо задана вручную через аргументы командной строки и меню. Меню содержит строку статуса, что позволяет контролировать текущее состояние приложений.

## Основные возможности

- **Интерактивное текстовое меню** со строкой статуса и описанием доступных команд
- **Загрузка конфигурации** из JSON-файла через параметр командной строки `--config`
- **Регистронезависимые команды** (например `ACTIVE`, `active` и `Active` работают одинаково)
- **Обработка непечатных символов** при вводе
- **Цветная индикация** состояния (активный или неактивный режим Client выделяется цветом)
- **Позиционные аргументы** - все параметры команд вводятся непосредственно после имени команды
- **Валидация вводимых данных** с сообщениями об ошибках

## Процесс сборки

### Требования
- CMake 3.14+
- C++23 совместимый компилятор (протестировано с GCC 12)
- Linux (протестировано в Ubuntu 24.04)

> **Примечание:** для проверки IP-адресов используется POSIX-функция `inet_pton`, поэтому приложение работает только на Posix-совместимых системах. Поддержка Windows не предусмотрена.

### Компоненты

Проект состоит из следюущих компонентов:
- **common_lib** — статическая библиотека общего назначения. Содержит утилиты для работы со строками, сетью, протоколами, валидацию данных, логирования, парсинг JSON, базовые классы меню, парсеров команд и конфигурации. Используется как клиентом, так и сервером.
- **client_lib** — статическая библиотека клиентского приложения.
- **server_lib** — статическая библиотека серверного приложения.
- **client** — исполняемый файл. Линкуется с `client_lib`.
- **server** — исполняемый файл. Линкуется с `server_lib`.
- **app_tests** — исполняемый файл с модульными тестами. Линкуется с `client_lib` (для тестирования клиентской части) и `GTest`. Требует предварительной сборки `client_lib`.

Все внешние зависимости (rang, json, cli11, spdlog, frozen) подключаются к общей библиотеке common_lib, а клиентские и серверные модули (client_lib, server_lib) получают доступ к этим библиотекам через линковку с common_lib.

### Сборка

```bash
# клонирование репозитория
git clone git@github.com:folp3x/protei.git
cd protei

# сборка Client и Server
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON
cmake --build build --target client server
# для ускорения сборки можно использовать флаг --parallel (-j)
cmake --build build --target client server -j

# при необходимости указать путь к компилятору
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON \
    -DCMAKE_C_COMPILER=/usr/bin/gcc-12 \
    -DCMAKE_CXX_COMPILER=/usr/bin/g++-12

# запуск Client с примером конфигурации
cd build/client
./client --config ./data/client_config.json

# запуск Server с примером конфигурации
cd build/server
./server --config ./data/server_config.json

# сборка тестов (Client также должен быть собран)
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_TESTS=ON
cmake --build build --target app_tests
# для ускорения сборки можно использовать флаг --parallel (-j)
cmake --build build --target app_tests -j

# запуск тестов
cd build/tests
./app_tests
```

## Примеры использования Client

### Строка статуса

В меню отображается шапка с актуальной информацией:

- **IMSI** — идентификатор абонента
- **State** — текущее состояние (active или inactive)
- **Location** — вектор позиции в формате (X, Y, Z)
- **Protocol** — текущий протокол передачи данных (binary или json)

### Доступные команды

`exit`

Завершает работу.

```bash
> exit
Exiting app...
```

`active`

Меняет состояние по булеву значению.

```bash
> active true
Status changed to active

> active false
Status changed to inactive

> active 1
Status changed to active

> active 0
Status changed to inactive
```

`move`

Меняет значение вектора позиции. В зависимости от количества переданных аргументов меняются определенные составляющие вектора.

```bash
> move 1.1
Position changed to (1.1, 0, 0)

> move 1.1 2
Position changed to (1.1, 2, 0)

> move 1.1 2 3
Position changed to (1.1, 2, 3)
```

`protocol`

Задает способ представления данных при передаче.

```bash
# выбор бинарного формата
> protocol binary
или
> protocol b
Protocol changed to binary

# выбор JSON-формата
> protocol json
или
> protocol j
Protocol changed to json
```
### Аргументы командной строки

Приложение поддерживает как загрузку конфигурации из файла, так и прямое указание параметров. При этом должен быть указан либо `--config` либо все конфигурационные опции. `--config` можно комбинировать с другими опциями, в таком случае опции командной строки переопределяют параметры конфигурационного файла.

```bash
# загрузка полной конфигурации из JSON
./client --config path_to_json

# указание параметров по отдельности
./client --ip 127.0.0.1 --port 61000 --imei 123456789012345 --imsi 543210987654321 --loc 7 6 2
```

Доступны следующий опции:

| Опция | Тип данных | Описание |
|-------|-----|----------|
| `-a, --ip` | IPv4 | IP-адрес |
| `-p, --port` | integer | Номер порта |
| `-e, --imei` | char[15] | Идентификатор устройства |
| `-i, --imsi` | char[15] | Идентификатор абонента |
| `-l, --loc` | real[3] | Вектор позиции (X Y Z) |
| `-k, --config` | string | Путь к JSON-файлу конфигурации |

### Пример конфигурационного файла

```json
{
    "ip": "127.0.0.1",
    "port": 61000,
    "imei": "123456789012345",
    "imsi": "543210987654321",
    "loc": [7, 6, 2]
}
```

> **Примечание**: все поля являются обязательными.

## Примеры использования Server

### Строка статуса

В меню отображается шапка, которая содержит **Location** — вектор позиции в формате (X, Y, Z)

### Доступные команды

`exit`

Завершает работу.

```bash
> exit
Exiting app...
```

`dist`

Вычисляет евклидово расстояние от своей позиции до указанной.
Например, если своей позиция (1, 2, 3):

```bash
> dist 2 3 3
Distance: 1.4142
```

### Аргументы командной строки

Приложение поддерживает как загрузку конфигурации из файла, так и прямое указание параметров. При этом должен быть указан либо `--config` либо все конфигурационные опции. `--config` можно комбинировать с другими опциями, в таком случае опции командной строки переопределяют параметры конфигурационного файла.

```bash
# загрузка полной конфигурации из JSON
./server --config path_to_json

# указание параметров по отдельности
./server --ip 0.0.0.0 --port 62000 --loc 1 2 3
```

Доступны следующий опции:

| Опция | Тип данных | Описание |
|-------|-----|----------|
| `-a, --ip` | IPv4 | IP-адрес |
| `-p, --port` | integer | Номер порта |
| `-l, --loc` | real[3] | Вектор позиции (X Y Z) |
| `-k, --config` | string | Путь к JSON-файлу конфигурации |
| `-n, --nodes` | string | Путь к JSON-файлу nodes |

> **Примечание**: для опции --nodes реализована только проверка наличия файла .json. Считывание данных из файла не реализовано.

### Пример конфигурационного файла

```json
{
    "ip": "0.0.0.0",
    "port": 62000,
    "loc": [1, 2, 3]
}
```

## Тестирование

Тестами покрыты:

- **CLI-парсер клиента** — парсинг опций `--config` и `--help`, валидация аргументов, проверка наличия всех конфигурационных опций, переопределение конфигурации.
- **Парсер команд клиента** — команда `move` (без аргументов, с 1-3 аргументами, с лишними, с невалидными), неизвестные команды, пустые команды.
- **Парсер конфигурации клиента** — корректный JSON, отсутствие полей, неверные типы (порт как строка или вещественное число), пустой или невалидный JSON.
- **Location** — перемещение с 0-4 координатами, `toStr()`, сравнение координат.
- **NetworkAddress** — конструкторы от IP и порта (числа и строки), парсинг из строки вида `"ip:port"`.
- **Validator** — проверка IP, порта, IMEI и IMSI, пути к JSON.

## Логирование

Логгер инициализируется в начале работы приложения и пишет в файл с **почасовой ротацией** в директорию `logs/` (директория располагается радом с исполняемым файлом client).

**Формат названия файла:**

```txt
app_name_2025-05-12_14
```

**Формат лога:**

```txt
[2025-05-12 14:30:00] [level] [file:function] message
```

**Когда и что логируется:**

| Уровень | Когда |
|---------|-------|
| `critical` | Ошибки в `main` (нет конфига, неверные аргументы командной строки) |
| `info` | Получение команды от пользователя и её выполнение |
| `debug` | Вызов конструкторов и операторов копирования и перемещения |

> Примечание: конструкторы и операторы перемещения явно определены и логируются в классах `Location`, `NetworkAddress`, `App`, `MenuItem*`.

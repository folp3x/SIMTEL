# Консольные приложения Client и Server

## Назначение

Приложение Client предоставляет консольный интерфейс с интерактивным текстовым меню. Конфигурация может быть загружена из JSON-файла либо задана через аргументы командной строки.

## Стек разработки

Стек разработки включает:

- CMake 3.14
- g++ 12.0
- c++ 23

Приложения разработаны под Linux и протестированы в WSL (Ubuntu 24.04).

## Компоненты

Проект состоит из следующих компонентов:
- **common_lib** — статическая библиотека общего назначения. Содержит функционал, который используется как в Client, так и в Server.
- **client_lib** — статическая библиотека клиентского приложения.
- **server_lib** — статическая библиотека серверного приложения.
- **client** — исполняемый файл. Линкуется с `client_lib`.
- **server** — исполняемый файл. Линкуется с `server_lib`.
- **common_tests** — исполняемый файл с тестами `common_lib` (требует предварительной сборки тестируемой библиотеки).
- **client_tests** — исполняемый файл с тестами `client_lib` (требует предварительной сборки тестируемой библиотеки).

Все внешние зависимости подключаются к общей библиотеке common_lib, а клиентские и серверные модули (client_lib, server_lib) получают доступ к этим библиотекам через линковку с common_lib.

## Использование системы

```bash
# установка зависимостей
apt install sqlite3 libsqlite3-dev

# клонирование репозитория
git clone git@github.com:folp3x/protei.git
cd protei

# сборка клиента и сервера
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON
cmake --build build --target client server
# для ускорения сборки можно использовать флаг --parallel (-j)
cmake --build build --target client server -j

# при необходимости указать путь к компилятору
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON \
    -DCMAKE_C_COMPILER=/usr/bin/gcc-12 \
    -DCMAKE_CXX_COMPILER=/usr/bin/g++-12

# запуск сервера
cd build/server
./server -k ./data/config/config.json

# запуск клиентов
cd build/client
./client -k ./data/config/config1.json
./client -k ./data/config/config2.json

# сборка тестов common_lib
cmake -S . -B build -DBUILD_COMMON_TESTS=ON
cmake --build build --target common_tests

# запуск тестов common_lib
cd build/common/tests
./common_tests

# сборка тестов client_lib
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_CLIENT_TESTS=ON
cmake --build build --target client_tests

# запуск тестов client_lib
cd build/client/tests
./client_tests
```

## Примеры использования Client

### Строка статуса

В меню отображается шапка с актуальной информацией:

- **IMSI** — идентификатор абонента
- **State** — текущее состояние (active или inactive)
- **Location** — вектор позиции
- **Protocol** — текущий протокол передачи данных (binary или json)
- **Signal** — уровень сигнала от 0 до 100

### Доступные команды

`exit`

Завершает работу.

```bash
> exit
Exiting app...
```

`active`

Меняет состояние по булевому значению.

```bash
> active true
Status changed to active

> active false
Status changed to inactive

> active 1
Status changed to active

> active 0
Status changed to inactive
```

`move`

Меняет значение вектора позиции.

```bash
> move 1.1
Position changed to (1.1, 0, 0)

> move 1.1 2
Position changed to (1.1, 2, 0)

> move 1.1 2 3
Position changed to (1.1, 2, 3)
```

`protocol`

Задает способ представления данных для сетевого обмена.

```bash
# выбор бинарного формата
> protocol binary
или
> protocol b
Protocol changed to binary

# выбор JSON
> protocol json
или
> protocol j
Protocol changed to json
```
### Аргументы командной строки

Приложение поддерживает как загрузку конфигурации из файла, так и прямое указание параметров. При этом должен быть указан либо `--config` либо все конфигурационные опции. `--config` можно комбинировать с другими опциями, в таком случае опции командной строки переопределяют параметры конфигурационного файла.

```bash
# загрузка полной конфигурации из JSON
./client --config path_to_json

# указание параметров по отдельности
./client --ip 127.0.0.1 --port 61000 --imei 123456789012345 --imsi 543210987654321 --loc 7 6 2
```

Доступны следующие опции:

| Опция | Тип данных | Описание |
|-------|-----|----------|
| `-a, --ip` | IPv4 | IP-адрес сервера |
| `-p, --port` | integer | Номер порта сервера |
| `-e, --imei` | char[15] | Идентификатор устройства |
| `-i, --imsi` | char[15] | Идентификатор абонента |
| `-l, --loc` | real[1] | Вектор позиции |
| `-k, --config` | string | Путь к JSON-файлу конфигурации |

### Пример конфигурационного файла

```json
{
    "ip": "127.0.0.1",
    "port": 61000,
    "imei": "123456789012345",
    "imsi": "543210987654321",
    "loc": [7]
}
```

> **Примечание**: все поля являются обязательными.

## Примеры использования Server

### Аргументы командной строки

Приложение поддерживает как загрузку конфигурации из файла. Дополнительно, порт, указанный в конфигурационном файле, можно переопределить аргументов командной строки.


| Опция | Тип данных | Описание |
|-------|-----|----------|

## Тестирование

Тестами покрыты:

- **CLI-парсер клиента** — парсинг опций `--config` и `--help`, валидация аргументов, проверка наличия всех конфигурационных опций, переопределение конфигурации.
- **Парсер команд клиента** — команда `move` (без аргументов, с 1-3 аргументами, с лишними, с невалидными), неизвестные команды.
- **Парсер конфигурации клиента** — корректный JSON, отсутствие полей, неверные типы (порт как строка или вещественное число), пустой или невалидный JSON.
- **Location** — перемещение с 0-4 координатами, метод `toStr()`, сравнение координат.
- **NetworkAddress** — конструкторы от IP и порта (числовых и строковых), парсинг из строки вида `"ip:port"`.
- **Validator** — проверка IP, порта, IMEI и IMSI, пути к JSON-файлу.

## Логирование

Логгер инициализируется в начале работы приложения и пишет в файл с почасовой ротацией в директорию `logs/` (директория располагается рядом с исполняемым файлом client или server).

**Формат названия файлов:**

```txt
app_name_2025-05-12_14
```

**Формат логов:**

```txt
[2025-05-12 14:30:00] [level] [file:function] message
```

**Когда и что логируется:**

| Уровень | Когда |
|---------|-------|
| `critical` | Клиент: ошибки в `main` (нет конфига, неверные аргументы командной строки) |
| `info` | Клиент: получение команды от пользователя и её выполнение. |
| `debug` | Вызов конструкторов и операторов копирования и перемещения|

> Примечание: конструкторы и операторы перемещения явно определены и логируются в классах `Location`, `NetworkAddress`, `App`, `MenuItem*`.

## Клиент-серверный обмен

### Формат пакетов

Структура пакетов:

`[msgSize (4 байта, big-endian)][protocol (1 байт)][reqType (1 байт)][data]`

| protocol | Формат |
|-----------|--------|
| 0x00 | Binary |
| 0x01 | JSON |

### JSON

Data содержит JSON-строку.

### Binary

Data содержит бинарные данные (в случае передачи чисел они передаются в big-endian).

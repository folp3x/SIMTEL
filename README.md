# SIMTEL - имитация LTE-сети

## Назначение

SIMTEL представляет собой программный комплекс для моделирования базовых механизмов LTE-сети.

Система состоит из серверного приложения, реализующего основные элементы EPC и радиосети, и клиентских приложений, имитирующих мобильные терминалы (UE).

Поддерживаются следующие функции:

- регистрация UE в сети через MME;
- подключение к eNode-B на основе уровня сигнала;
- выдача временных идентификаторов M-TMSI;
- хранение данных абонентов в HLR и VLR;
- передача SMS между абонентами через SMSC;
- временное хранение недоставленных сообщений;
- доставка уведомлений о результате отправки SMS;
- поддержка процедуры handover между базовыми станциями.

## Архитектура системы

Система состоит из следующих подсистем.

### UE (User Equipment)

Клиентское приложение, имитирующее мобильный терминал.

Каждый UE обладает следующими идентификаторами:

- IMEI;
- IMSI;
- M-TMSI (назначается после регистрации).

UE поддерживает:

- включение и выключение терминала (команда `active`);
- регистрацию и отключение от сети;
- перемещение в одномерном пространстве (команда `move`);
- отправку SMS (команда `sms`);
- получение SMS (команда `delivered`);
- получение отчётов о доставке (команды `sent` и `dialog`).

### eNode-B

Имитация базовой станции LTE.

Функции:

- расчёт уровня сигнала до UE;
- обслуживание подключённых UE;
- пересылка SMS из SMSC;
- поддержка процедуры handover.

### MME

Узел управления мобильностью.

Функции:

- регистрация UE;
- выдача M-TMSI;
- взаимодействие с HLR;
- взаимодействие с VLR;
- маршрутизация SMS.

### SMSC

Центр обработки SMS.

Функции:

- хранение SMS до доставки;
- контроль времени жизни сообщений;
- удаление доставленных и просроченных сообщений.

### Register (HLR/EIR)

Подсистема хранения данных абонентов.

Содержит:

- IMSI;
- IMEI;
- MSISDN;
- статус абонента (активен/заблокирован);
- информацию об обслуживающем MME (id).

> Дополнительно хранится M-TIMSI

### Visitor List (VLR)

Подсистема временного хранения зарегистрированных абонентов.

Содержит:

- M-TMSI;
- IMSI;
- IMEI;
- MSISDN;
- обслуживающую базовую станцию (в виде указателя).

## Модель сети

Используется одномерная система координат.

Параметры сети:

| Объект    | Координата X |
| --------- | ------------ |
| eNode-B-1 | -100         |
| eNode-B-2 | 100          |

Радиус обслуживания каждой базовой станции составляет 120 единиц (может быть изменен в конфигурационном файле).

Уровень сигнала вычисляется по формуле:

$$
signal = (1 - abs(distance) / radius) * 100
$$

где distance — расстояние между UE и базовой станцией.

В результате получается число от 0 до 100, где:
- 0 - сигнал отсутствует
- чем ближе число к 100, тем лучше сигнал

При handover UE подключается к базовой станции с максимальным уровнем сигнала.

## Компоненты проекта

Проект состоит из следующих компонентов:

- **common_lib** — статическая библиотека общего назначения;
- **client_lib** — статическая библиотека клиентского приложения;
- **server_lib** — статическая библиотека серверного приложения;
- **client** — исполняемый файл UE;
- **server** — исполняемый файл SIMTEL;
- **common_tests** — тесты общей библиотеки;
- **client_tests** — тесты клиентской библиотеки.

Все внешние зависимости подключаются к общей библиотеке common_lib, а клиентские и серверные модули получают доступ к ним через линковку с common_lib.

## Использование системы

```bash
# установка зависимостей
apt install sqlite3 libsqlite3-dev

# клонирование репозитория
git clone git@github.com:folp3x/protei.git
cd protei

# сборка клиента и сервера
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON
cmake --build build --target client server

# сборка с использованием нескольких потоков
cmake --build build --target client server -j

# указание компилятора
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON \
    -DCMAKE_C_COMPILER=/usr/bin/gcc-12 \
    -DCMAKE_CXX_COMPILER=/usr/bin/g++-12

# запуск сервера
cd build/server
./server -k ./data/config/config.json

# запуск клиентов
cd build/client
./client -k ./data/config/config1.json
./client -k ./data/config/config2.json
```

## Тестирование

Тестами покрыты:

- **CLI-парсер клиента** — парсинг опций `--config` и `--help`, валидация аргументов, проверка наличия всех конфигурационных опций, переопределение конфигурации.
- **Парсер команд клиента** — команда `move` (без аргументов, с 1-3 аргументами, с лишними, с невалидными), неизвестные команды.
- **Парсер конфигурации клиента** — корректный JSON, отсутствие полей, неверные типы (порт как строка или вещественное число), пустой или невалидный JSON.
- **Location** — перемещение с 0-4 координатами, метод `toStr()`, сравнение координат.
- **NetworkAddress** — конструкторы от IP и порта (числовых и строковых), парсинг из строки вида `"ip:port"`.
- **Validator** — проверка IP, порта, IMEI и IMSI, пути к JSON-файлу.

## Реализуемые сценарии

Система поддерживает следующие сценарии:

- доставка SMS зарегистрированному абоненту;
- доставка SMS абоненту, подключившемуся после отправки сообщения;
- хранение SMS в SMSC до истечения TTL;
- доставка SMS после handover отправителя.

# Консольные приложения Client и Server

Клиент позволяет управлять параметрами подключения и передачи данных. Сервер позволяет вычислять расстояние до заданной позиции.

## Краткое описание

Оба приложения предоставляют консольный интерфейс с интерактивным текстовым меню. Конфигурация может быть загружена из JSON-файла либо задана через аргументы командной строки. Приложения могут работать по отдельности (сервер может вычислять расстояние по команде из текстового меню) или обмениваться данными по сети. В случае клиент-серверного обмена клиент отправляет серверу позицию (когда его состояние active и позиция изменилась). Сервер считает расстояние до своей позиции и возвращает его клиенту. Если сервер недоступен, клиент продолжает работать (расстояние в этом случае не обновляется).

## Основные возможности

- **Интерактивное текстовое меню** со строкой статуса и описанием доступных команд
- **Загрузка конфигурации** из JSON-файла через параметр командной строки `--config`
- **Регистронезависимые команды** (например `ACTIVE`, `active` и `Active` работают одинаково)
- **Обработка непечатных символов** при вводе
- **Цветная индикация** состояния (активный или неактивный режим клиента выделяется цветом, сообщения для пользователя выделяются цветом в зависимости от типа - `info` или `err`)
- **Позиционные аргументы** - все параметры команд вводятся непосредственно после имени команды
- **Валидация вводимых данных** с сообщениями об ошибках
- **Клиент-серверный обмен** - клиент отправляет позицию, сервер возвращает расстояние

## Процесс сборки

### Требования

- CMake 3.14+
- C++23 совместимый компилятор (протестировано с GCC 12)
- Linux (протестировано в Ubuntu 24.04)

> **Примечание:** поддержка Windows не предусмотрена.

### Компоненты

Проект состоит из следующих компонентов:
- **common_lib** — статическая библиотека общего назначения. Содержит утилиты для работы со строками, сетью, протоколами, валидацию данных, логирования, парсинг JSON, базовые классы меню, парсеров команд и конфигурации. Используется как клиентом, так и сервером.
- **client_lib** — статическая библиотека клиентского приложения.
- **server_lib** — статическая библиотека серверного приложения.
- **client** — исполняемый файл. Линкуется с `client_lib`.
- **server** — исполняемый файл. Линкуется с `server_lib`.
- **common_tests** — исполняемый файл с тестами `common_lib` (требует предварительной сборки тестируемой библиотеки).
- **client_tests** — исполняемый файл с тестами `client_lib` (требует предварительной сборки тестируемой библиотеки).

Все внешние зависимости подключаются к общей библиотеке common_lib, а клиентские и серверные модули (client_lib, server_lib) получают доступ к этим библиотекам через линковку с common_lib.

### Сборка

```bash
# клонирование репозитория
git clone git@github.com:folp3x/protei.git
cd protei

# сборка клиента и сервера
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON
cmake --build build --target client server
# для ускорения сборки можно использовать флаг --parallel (-j)
cmake --build build --target client server -j

# при необходимости указать путь к компилятору
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_SERVER=ON \
    -DCMAKE_C_COMPILER=/usr/bin/gcc-12 \
    -DCMAKE_CXX_COMPILER=/usr/bin/g++-12

# тест клиент-серверного взаимодействия
./client_server_test.sh

# в тесте 3 клиента выполняют по несколько команд (protocol и active, move и active а также active и move)
# результаты выполнения (весь вывод клиентов) выводится в качестве результата тестов.

# запуск сервера
cd build/server
./server --config ./data/config.json

# запуск клиентов
cd build/client
./client --config ./data/config1.json
./client --config ./data/config2.json
./client --config ./data/config3.json

# сборка тестов common_lib
cmake -S . -B build -DBUILD_COMMON_TESTS=ON
cmake --build build --target common_tests

# запуск тестов common_lib
cd build/common/tests
./common_tests

# сборка тестов client_lib
cmake -S . -B build -DBUILD_CLIENT=ON -DBUILD_CLIENT_TESTS=ON
cmake --build build --target client_tests

# запуск тестов client_lib
cd build/client/tests
./client_tests
```

## Примеры использования клиента

### Строка статуса

В меню отображается шапка с актуальной информацией:

- **IMSI** — идентификатор абонента
- **State** — текущее состояние (active или inactive)
- **Location** — вектор позиции в формате (X, Y, Z)
- **Protocol** — текущий протокол передачи данных (binary или json)

Дополнительно отображается строка с адресом сервера и расстоянием до него.

### Доступные команды

`exit`

Завершает работу.

```bash
> exit
Exiting app...
```

`active`

Меняет состояние по булевому значению. Если предыдущее состояние было 'inactive' запрашивается расстояние до сервера.

```bash
> active true
Status changed to active

> active false
Status changed to inactive

> active 1
Status changed to active

> active 0
Status changed to inactive
```

`move`

Меняет значение вектора позиции. В зависимости от количества переданных аргументов меняются определенные составляющие вектора. Если новая позиция отличается от предыдущей запрашивается расстояние до сервера.

```bash
> move 1.1
Position changed to (1.1, 0, 0)

> move 1.1 2
Position changed to (1.1, 2, 0)

> move 1.1 2 3
Position changed to (1.1, 2, 3)
```

`protocol`

Задает способ представления данных при передаче.

```bash
# выбор бинарного формата
> protocol binary
или
> protocol b
Protocol changed to binary

# выбор JSON
> protocol json
или
> protocol j
Protocol changed to json
```
### Аргументы командной строки

Приложение поддерживает как загрузку конфигурации из файла, так и прямое указание параметров. При этом должен быть указан либо `--config` либо все конфигурационные опции. `--config` можно комбинировать с другими опциями, в таком случае опции командной строки переопределяют параметры конфигурационного файла.

```bash
# загрузка полной конфигурации из JSON
./client --config path_to_json

# указание параметров по отдельности
./client --ip 127.0.0.1 --port 61000 --imei 123456789012345 --imsi 543210987654321 --loc 7 6 2
```

Доступны следующие опции:

| Опция | Тип данных | Описание |
|-------|-----|----------|
| `-a, --ip` | IPv4 | IP-адрес сервера |
| `-p, --port` | integer | Номер порта сервера |
| `-e, --imei` | char[15] | Идентификатор устройства |
| `-i, --imsi` | char[15] | Идентификатор абонента |
| `-l, --loc` | real[3] | Вектор позиции (X Y Z) |
| `-k, --config` | string | Путь к JSON-файлу конфигурации |

### Пример конфигурационного файла

```json
{
    "ip": "127.0.0.1",
    "port": 61000,
    "imei": "123456789012345",
    "imsi": "543210987654321",
    "loc": [7, 6, 2]
}
```

> **Примечание**: все поля являются обязательными.

### Многопоточность

В текущей реализации клиент не является многопоточным, однако реализован функционал обновления дистанции с заданной периодичностью в отдельном потоке (сейчас не используется но может быть использован если расстояние нужно обновлять независимо от команды move).

## Примеры использования сервера

### Строка статуса

В меню отображается шапка, которая содержит **Location** — вектор позиции в формате (X, Y, Z).

### Доступные команды

`exit`

Завершает работу.

```bash
> exit
Exiting app...
```

`dist`

Вычисляет евклидово расстояние от своей позиции до указанной.
Например, если своя позиция (1, 2, 3):

```bash
> dist 2 3 3
Distance: 1.4142
```

### Аргументы командной строки

Приложение поддерживает как загрузку конфигурации из файла, так и прямое указание параметров. При этом должен быть указан либо `--config` либо все конфигурационные опции. `--config` можно комбинировать с другими опциями, в таком случае опции командной строки переопределяют параметры конфигурационного файла.

```bash
# загрузка полной конфигурации из JSON
./server --config path_to_json

# указание параметров по отдельности
./server --ip 0.0.0.0 --port 62000 --loc 1 2 3
```

Доступны Следующие опции:

| Опция | Тип данных | Описание |
|-------|-----|----------|
| `-a, --ip` | IPv4 | IP-адрес |
| `-p, --port` | integer | Номер порта |
| `-l, --loc` | real[3] | Вектор позиции (X Y Z) |
| `-k, --config` | string | Путь к JSON-файлу конфигурации |
| `-n, --nodes` | string | Путь к JSON-файлу nodes |

> **Примечание**: для опции --nodes реализована только проверка наличия файла .json. Считывание данных из файла не реализовано.

### Пример конфигурационного файла

```json
{
    "ip": "0.0.0.0",
    "port": 62000,
    "loc": [1, 2, 3]
}
```

### Многопоточность

Сервер является многопоточным. Обработка команд пользователя и обработка подключений клиентов происходит в разных потоках. Дополнительно, для обработки каждого клиента создается отдельный поток.

## Тестирование

Тестами покрыты:

- **CLI-парсер клиента** — парсинг опций `--config` и `--help`, валидация аргументов, проверка наличия всех конфигурационных опций, переопределение конфигурации.
- **Парсер команд клиента** — команда `move` (без аргументов, с 1-3 аргументами, с лишними, с невалидными), неизвестные команды, пустые команды.
- **Парсер конфигурации клиента** — корректный JSON, отсутствие полей, неверные типы (порт как строка или вещественное число), пустой или невалидный JSON.
- **Location** — перемещение с 0-4 координатами, `toStr()`, сравнение координат.
- **NetworkAddress** — конструкторы от IP и порта (числа и строки), парсинг из строки вида `"ip:port"`.
- **Validator** — проверка IP, порта, IMEI и IMSI, пути к JSON-файлу.

## Логирование

Логгер инициализируется в начале работы приложения и пишет в файл с **почасовой ротацией** в директорию `logs/` (директория располагается рядом с исполняемым файлом client или server).

**Формат названия файлов:**

```txt
app_name_2025-05-12_14
```

**Формат логов:**

```txt
[2025-05-12 14:30:00] [level] [file:function] message
```

**Когда и что логируется:**

| Уровень | Когда |
|---------|-------|
| `critical` | Клиент: ошибки в `main` (нет конфига, неверные аргументы командной строки) |
| `info` | Клиент: получение команды от пользователя и её выполнение. Клиент и сервер: отправка и получение позиции и расстояния |
| `warn` | Слишком много клиентов подключаются к серверу, ошибка обновления дистанции на клиенте |
| `debug` | Вызов конструкторов и операторов копирования и перемещения, отправка данных по сети в json и бинарных форматах |

> Примечание: конструкторы и операторы перемещения явно определены и логируются в классах `Location`, `NetworkAddress`, `App`, `MenuItem*`.

## Клиент-серверный обмен

### Формат пакетов

Структура пакета:  
`[networkId (1 байт)][size (4 байта, big-endian)][data]`

| networkId | Формат |
|-----------|--------|
| 0x00 | Binary |
| 0x01 | JSON |

### JSON

Data содержит JSON-строку.

**Пример пакета Location (координаты [1, 2, 3]):**

```txt
[0x01] # networkId (JSON)
[0x00 0x00 0x00 0x10] # size = 15
{"loc":[1,2,3]}
```

**Пример пакета Distance (расстояние 5):**

```txt
[0x01] # networkId (JSON)
[0x00 0x00 0x00 0x0B] # size = 10
{"dist":5}
```

### Binary

Data содержит бинарные данные (целые числа, big-endian).

**Пример пакета Location (координаты [1, 2, 3]):**

```txt
[0x00] # networkId (Binary)
[0x00 0x00 0x00 0x0C] # size = 12
[0x00 0x00 0x00 0x01] # int32 1
[0x00 0x00 0x00 0x02] # int32 2
[0x00 0x00 0x00 0x03] # int32 3
```

**Пример пакета Distance (расстояние 5):**

```txt
[0x00] # networkId (Binary)
[0x00 0x00 0x00 0x04] # size = 4
[0x00 0x00 0x00 0x05] # int32 5
```
